# Copilot Studio API connection plan\n\nThis branch adds the Copilot Studio integration plan on top of firebase-db-connect.\n\n## Phase 1 - conversation entry\n\nThe first action is executed once when a new RE:DAY day starts, before the first simulation response.\n\n1. Create or reuse a stable conversationId for the Copilot conversation.\n2. Call POST https://re-day-api.onrender.com/chat/sessions.\n3. Pass the Copilot user identifier as x-user-id until Firebase Auth UID is available.\n4. Call GET /chat/sessions/{conversationId}/context and expose returned memories and summary to the orchestrator.\n5. Do not continue the day if session/context persistence fails.\n\n### Session request\n\nPOST /chat/sessions\n\nx-api-key must be configured as a secret in the Copilot action. The body is:\n\n```json\n{"conversationId":"<conversationId>","channel":"copilot-studio","title":"RE:DAY daily simulation"}\n```\n\n## Phase 2 - daily completion\n\nThe second action is executed only when the user has completed the day and the final summary is ready.\n\n1. Save the final Copilot answer with POST /chat/sessions/{conversationId}/messages.\n2. Save the structured day summary with PUT /chat/sessions/{conversationId}/summary.\n3. Save only explicitly detected long-term facts as memory candidates with POST /users/me/memories.\n4. Never mark a memory as confirmed without user confirmation.\n\n### Summary request\n\nPUT /chat/sessions/{conversationId}/summary\n\n```json\n{"summary":"<final day summary>","keyPoints":["<point>"],"nextActions":["<action>"],"completedAt":"<ISO-8601>"}\n```\n\n## Required action headers\n\n- x-api-key: Render secret COPILOT_API_KEY\n- x-user-id: temporary stable user id, replaced by Firebase Auth UID later\n- Content-Type: application/json\n\n## Failure policy\n\nThe Agent must surface a persistence
