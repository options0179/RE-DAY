# RE:DAY 제품 요구사항

## 상태와 범위

- 상태: 초안. 아래 기능은 사용자 검증과 팀의 범위 확정 전까지 확정 요구가 아니다.
- 이 문서는 사용자가 경험할 제품 흐름과 기능 후보를 정리한다. 현재 구현 상태는 [`../dev/SAD.md`](../dev/SAD.md)와 코드에서 확인한다.
- 외부 기획 문서는 이 문서를 작성할 때 참고한 자료다. 이후 개발은 이 저장소 문서와 Issue를 기준으로 관리하며 외부 문서에 대한 실시간 의존성을 두지 않는다.

## 서비스 정의

RE:DAY는 관심 있는 직무의 대표 업무 상황을 체험하고, 선택의 근거와 결과를 돌아보며, 다음에 확인할 직무 질문을 정리하도록 돕는 서비스다.

핵심 경험은 다음과 같다.

```text
관심 직무 탐색 → 업무 맥락 이해 → 단서 확인과 대응 → 결과 확인
→ 선택 근거 회고 → 직무 간 비교와 다음 확인 행동
```

제품의 가치는 가상 업무 상황을 통해 직무의 판단·협업 맥락을 살피고, 막연한 관심을 구체적인 비교 질문으로 바꾸는 데 있다. 가상 체험은 실제 근무 경험이나 직무 적합도 판정이 아니다.

## 사용자 경험 요구 후보

1. **직무 탐색**: 사용자가 관심 직무를 선택하고, 추천을 제공할 때는 추천 이유와 주요 업무를 확인할 수 있다.
2. **하루 브리핑**: 역할, 팀, 인물, 일정, 업무 목표, 제약 조건 등 상황을 이해하는 데 필요한 정보를 제공한다.
3. **상황 대응**: 사용자는 메신저·회의·요청·피드백 등 현실적인 상황에서 단서를 확인하고 선택지 또는 자유 입력으로 대응한다.
4. **정보 확인 행동**: 즉시 결론을 내리는 것 외에 팀원에게 묻거나 일정·자료·요청을 확인할 수 있다. 확인 결과는 검토된 시나리오 안에서 제공하고, 장면에 없는 사실을 즉석에서 만들어 내지 않는다.
5. **결과 확인**: 선택으로 업무 일정, 위험, 협업자 반응 등이 어떻게 달라졌는지 보여준다. 단순한 정답·오답 판정으로 끝내지 않는다.
6. **회고와 비교**: 사용자가 선택 이유와 예상 밖의 결과를 돌아보고, 여러 직무를 경험했다면 공통 항목으로 나란히 비교할 수 있다.
7. **다음 행동**: 체험에서 생긴 질문을 공고에서 확인하거나 현직자에게 물어볼 질문으로 정리·보관한다.
8. **기록과 재도전**: 회고와 질문을 다시 열 수 있고, 사용자가 원하면 같은 직무의 다른 상황이나 다른 선택을 이어서 체험한다. 영구 저장 방식은 별도 설계와 구현이 필요하다.

랜딩 화면, 선호 입력, 관심 직무 후보 보드, 지원 공고 메모는 위 흐름을 돕는 UI 후보로 검토한다. 사용자 가치가 검증되기 전에는 자동 공고 분석이나 복잡한 개인화가 필수 조건은 아니다.

## 프로토타입과 MVP 후보

기획 자료에는 서로 다른 단계의 범위가 제안되어 있다. 단계별로 구분하며, 아래 내용만으로 출시 범위가 확정된 것으로 보지 않는다.

### 검증용 프로토타입 후보

- 실제로 비교하고 싶은 직무 두 개
- 직무별 검토된 대표 상황 한 개
- 체험 시간은 직무당 약 10~15분을 목표로 하되 사용성 테스트로 조정
- 두 직무의 업무 목표, 협업 상대, 반복되는 판단, 시간 압박, 추가 질문을 비교하는 노트
- 영구 저장 없이도 비교 흐름의 유용성을 검증할 수 있음

초기 예시 직무는 UX 디자이너와 프런트엔드 개발자다. 마케팅 기획자는 초기 직무 후보로 제시되었지만, 첫 비교 실험에 포함할지는 확정되지 않았다.

### 첫 MVP 후보

- 검토된 직무와 제한된 상황을 제공한다. 기획 초안은 직무 3개와 직무당 1~2개 상황을 후보로 두었다.
- 두 직무 비교, 체험 회고, 질문 보관, 관련된 다음 체험 제안을 검토한다.
- 후보 보드, 근거 출처 표시, 비교 노트, 확인 질문 카드는 제안된 기능이며 하나의 MVP 범위로 확정되지 않았다.
- 저장 기능을 채택한다면 데이터 소유권, 보존, 삭제, 로그인 여부와 영속 저장소를 먼저 결정한다.

## 범위에서 제외하거나 검증을 미룰 항목

- 취업 가능성 또는 직무 적합도 점수
- 선택을 정답·오답으로 채점하거나 사용자의 성격·역량을 단정하는 기능
- 사용자 간 랭킹, 출석 보상, 범용 뱃지
- 검토 없이 생성하는 무제한 시나리오
- 대규모 직무 카탈로그와 공고 자동 수집·파싱
- 직무 체험과 무관한 장시간 자유 대화를 핵심 경험으로 삼는 것

동일 상황의 선택 비교, 다른 직무의 유사 상황, 지원 전 요약 브리프, 직무 탐색 지도는 핵심 가치와 시나리오 품질이 검증된 뒤 다시 판단한다.

## 제품 수준의 완료 기준 후보

체험이 재미있었는지만 보지 않고, 사용자가 두 직무의 차이를 자기 말로 설명하는지, 새로 생긴 질문이 구체적인지, 공고 확인이나 현직자 대화 같은 다음 행동으로 이어지는지를 관찰한다. 초기 사용자 조사 전에는 임의의 전환율 목표를 확정하지 않는다.

시나리오의 사실 정보와 가상 설정은 사용자에게 구분해서 보여준다. 조직마다 업무가 다를 수 있음을 밝히며, 한 시나리오를 직무 전체의 대표 사실로 일반화하지 않는다.
